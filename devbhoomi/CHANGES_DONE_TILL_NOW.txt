7. SIGNUP: PHONE NUMBER OTP VERIFICATION (Message Central)
--------------------------------------------------------------
New requirement on the Signup page: a phone number must now be verified
with an OTP before an account can be created — same pattern as the
existing email verification step, side by side with it. Reduces fake/junk
accounts signing up with numbers they don't actually control.

How it works:
- New backend endpoints (mirroring the email ones):
  POST /api/auth/signup/phone-otp/request  { phone }
  POST /api/auth/signup/phone-otp/verify   { phone, code }
  -> returns a short-lived phoneVerificationToken (20 min), which the
  frontend now sends along with emailVerificationToken when submitting
  POST /api/auth/signup. Signup is rejected if either token is missing,
  expired, or doesn't match the phone/email actually submitted.
- SMS is sent via Message Central's "Verify Now" API using the
  MESSAGE_CENTRAL_CUSTOMER_ID / MESSAGE_CENTRAL_EMAIL /
  MESSAGE_CENTRAL_PASSWORD env vars (new file:
  backend/src/utils/messageCentral.js). Message Central generates and
  owns the OTP itself (unlike the existing Brevo SMS path, which sends a
  code we generate) — we just trigger the send and later ask Message
  Central "was this code right?" via their validate API.
  - Auth token from Message Central is cached in memory (~6 days) instead
    of being re-fetched on every OTP send.
  - This is now the DEFAULT SMS OTP provider whenever
    MESSAGE_CENTRAL_CUSTOMER_ID is set — this also upgrades the existing
    OTP-login and "verify phone in Settings" flows automatically, not
    just signup, since they share the same underlying otp.js. If the
    Message Central vars are ever unset, everything falls back to
    exactly the previous Brevo SMS behaviour automatically.
- Frontend: Signup page's phone number field now has the same "Send OTP
  -> enter code -> Verified" flow as the email field already had. The
  Create Account button is blocked until both email and phone show
  Verified.
- .env / .env.example / render.yaml updated with the three
  MESSAGE_CENTRAL_* variables.
